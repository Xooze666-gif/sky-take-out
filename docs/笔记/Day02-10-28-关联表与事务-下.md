## 核心讲解

### 多对多：套餐和菜品
- 双向多对多，靠中间表 `setmeal_dish`（setmeal_id + dish_id + copies）
- **快照补全**：前端只传 dishId+copies，后端 `selectBatchIds` 一次查出所有菜品补 name/price
  - 为什么不循环查：N+1 问题（查 N 次数据库）
  - 为什么不信前端传价：前端不可信，否则套餐价和菜单对不上
- **防篡改**：`setId(null)` 强制自增，防前端带 id 覆盖已有数据

### @Transactional 的两个必知点
1. **默认只回滚 RuntimeException 和 Error**，检查异常（如 IOException）不回滚，需写 `rollbackFor = Exception.class`
2. **自调用失效**：同类方法 A 调 B，B 上的 @Transactional 不生效——Spring 事务靠代理对象，自调用绕过了代理。解法：拆到另一个类，或注入自身代理

### 为什么更新用「先删后插」
- 比对新旧差异（哪条改/删/增）逻辑复杂易错
- 事务保护下「先删后插」简单可靠
- 代价：口味 id 会变，但业务上没人引用口味 id，无所谓

### 删除顺序：先子后主
先删口味再删菜品，反了会留孤儿数据（或触发外键报错）。
