## 使用规则
1. 每天只做一个文件，做完在文末打卡
2. 卡壳的题标红，当天或次日回对应笔记重学
3. 「新学日」看笔记里的讲解 + 对照真实代码；「对练日」全程口述不看稿；「动手日」改代码前记得先停应用、mvn package（不用 clean）
4. Day21 的 Redis 动手需要用户自己先装好 Redis 环境（AI 不代装软件）
5. 全部 25 个文件都在本目录，文件名带日期，顺序即文件名顺序

## 配套源码精讲（真正吃透代码用）

25 天笔记是**进度骨架**（今天该学什么），精讲是**吃掉代码的原料**（这段代码到底在干嘛）。两者配合：按日程翻开当天笔记 → 需要深挖某个方法时去翻对应精讲。

**精讲统一采用「八层拆解法」**：① 场景 ② 数据（执行前后）③ 逐行拆 ④ SQL/实测证据 ⑤ 权衡 ⑥ 踩坑实录 ⑦ 缺口 ⑧ 面试 30 秒版

| 篇 | 主题 | 核心收获 | 状态 |
|---|---|---|---|
| 00 | **索引与阅读路线** | 15 篇怎么排顺序读、考点反查表、怎么自己抓 SQL | ✅ |
| 01 | 购物车加购 | 动态条件一行顶四种组合；购物车用活价；`amount` 是单价不是总价 | ✅ |
| 02 | 提交订单 | `@Transactional` 的数据库真身（autocommit=0…commit）；地址快照；订单号设计；**总额信任前端 + 订单详情越权**两个缺口 | ✅ |
| 03 | 支付幂等 | 两次调用 SQL 对比证明幂等（第 2 次零写入）；`updateById` 全字段 vs 单字段；先查后改的并发缺口 | ✅ |
| 04 | 登录全链路（login + JwtUtil） | 密码为什么不在 SQL 里比；token 只放 empId；`iat`/`exp` 存秒不存毫秒；MD5 的技术债怎么讲 | ✅ |
| 05 | 拦截器与 ThreadLocal | 无 token 时 **0 条 SQL** 即 401；`create_user=1` 是整条链的活证据；`(Number)` 强转的坑 | ✅ |
